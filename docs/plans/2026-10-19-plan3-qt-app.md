# Plan 3 — Qt Application and Original Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `vtoast`, the desktop app: a tabbed main window whose Switcher tab is the Video Toaster 4.2 screen. Its Switcher panel is drawn pixel for pixel from the art inside `switcher.main`, above it sits a Project grid of the original crouton icons, Program and Preview monitor windows show the video, there is an audio mixer, input and recording settings, and live audio output. All of it drives the Plan 1 engine through the Plan 2 program loop.

**Architecture:** A new Qt-free static library `vt_assets` (`assets/`) reads the original files:
- Amiga hunk executables;
- the Switcher panel's button nodes and their planar art in `switcher.main`;
- Amiga colour fonts;
- crouton icons, through the engine's ILBM decoder.

It produces indexed bitmaps plus palettes, tested byte-for-byte against golden data from the Python reference tools, as Plan 1 did.

`vt_media` gains three things:
- a WASAPI audio output sink;
- a monitor feed carrying the Program and Preview pictures;
- a Switcher state snapshot for the UI.

The Qt executable `vtoast` (`app/`) draws the Toaster screen from `vt_assets` at whole-number zoom with nearest-neighbour pixels only. It never touches the `vt::Switcher` directly: actions go through `ProgramLoop::post`, and the display reads the snapshot.

**Tech Stack:**
- C++20, MSVC 14.44, CMake 3.31 + Ninja.
- Qt 6.8.3 (msvc2022_64, modules Core/Gui/Widgets/Test), installed at `../Qt/6.8.3/msvc2022_64` by aqtinstall.
- FFmpeg 9.0.2 (Plan 2).
- WASAPI (`Audioclient.h`, `Mmdeviceapi.h`).
- Catch2 v3.7.1 for the non-Qt libraries; Qt Test for widgets (offscreen platform).

**Spec:** `docs/2026-10-17-switcher-design.md` (§2, §3 item 6, §6, §8). Plans 1 and 2 are merged on `main`; their ledgers under `.superpowers/sdd/` hold rulings that still bind the engine and media code.

**Reverse-engineering source for the screen:** `../tools/re/SCREEN.md` and `../tools/re/switcher_layout.json`, produced from `switcher.main` (Video Toaster 4.06).
- The Switcher screen is 768×481, HIRES|LACE, depth 2.
- The Project half is at (64,44,640,200); the Switcher half is at (64,244,640,240).
- 70 button nodes are linked in nine lists at `$158–$17c(a5)`, with their 2-bit planar art and state tables.
- The T-bar has 86 images, chosen by position / 6.
- Three texts are drawn at run time in CGInterface 14.
- Project grid cells are 80×50 from (64,44), 8 columns by 4 visible rows.
- The palette is 000 555 999 DDD in RGB mode, and 000 842 7BC FFF in PREVIEW mode (Toaster-encoded, look unknown).
- "Selected" rotates colours inside a button's mask: 1→2, 2→3, 3→1.
- `../tools/re/render_layout.py` is the executable reference: `--extract` rebuilds the JSON from `switcher.main`, and with no option it renders the screen.

## Global Constraints

**Libraries and dependencies**
- `vt_engine`, `vt_media` and `vt_assets` stay free of Qt. Only `app/` (the `vtoast` executable and its tests) uses Qt.
- Qt comes only from `VT_QT_DIR`, a CMake cache path defaulting to `${CMAKE_SOURCE_DIR}/../Qt/6.8.3/msvc2022_64`, through `find_package(Qt6 6.8 REQUIRED COMPONENTS Core Gui Widgets Test)`.
- No QtMultimedia. Audio output is WASAPI in `vt_media`.
- `vtoast` gets the Qt DLLs via `windeployqt --no-translations --no-compiler-runtime` (POST_BUILD) and the FFmpeg DLLs via `vt_copy_ffmpeg_dlls`. Qt test executables run with Qt's `bin` prepended to PATH through CTest `ENVIRONMENT_MODIFICATION`.

**Pixels**
- Toaster art is decoded at run time from the original files under the Toaster data root, and is never committed as PNGs.
- Display is whole-number zoom with nearest-neighbour only (`QPainter` without `SmoothPixmapTransform`, or an exact per-pixel blit). No fractional scaling, no filtering.
- Account for `devicePixelRatio`, so one Toaster pixel is exactly N×N device pixels at 125% and 150% Windows scaling.
- Display pixel aspect: square pixels at whole-number zoom for now. The owner will judge the 10:11 question once the app runs; keep the zoom code in one place so an aspect option can be added later.

**Data root and threading**
- Toaster data root: the setting `toasterRoot`, defaulting to the build-time `VT_DATA_ROOT` (`${CMAKE_SOURCE_DIR}/..`). It is valid when `4.2/Programs/switcher.main` exists.
- Threading:
  - The UI thread never calls `vt::Switcher`.
  - Every operator action is `ProgramLoop::post`.
  - The UI reads `ProgramLoop::switcherState()`, a snapshot published every tick.
  - Monitor pictures arrive through `ProgramLoop::addMonitor`, which drops frames rather than blocking the loop.
  - The UI never blocks the loop thread.

**Screen palette (my call, adjustable)**
- The Switcher screen uses the RGB-mode palette `000 555 999 DDD` by default. This is proven from the binary and matches the manual's grey 4.0 screenshot.
- The PREVIEW-mode words `000 842 7BC FFF` are offered as the setting `panelPalette = preview`, labelled "Toaster-encoded, look unverified".
- Crouton icons use their own CMAP.

**Layout (my call)**
- The Switcher tab is the Toaster 4.x **Project/Switcher view** of the owner's 4.2/4.3 software: the Project grid on top and the Switcher panel below, at the exact screen coordinates above.
- Program and Preview monitors are separate top-level windows, standing in for the Toaster's external monitors.
- Paint, LightWave and Flyer tabs are present and disabled.

**Original behaviour to keep** (manual PDF 164 and 183-189; `../tools/re/manual_notes.md` lines 34-65 and 98-122)
- Mouse:
  - a bus button selects that source;
  - TAKE cuts;
  - AUTO runs the effect at the S/M/F speed;
  - the T-bar drags;
  - a single click on a crouton loads it as the current effect;
  - a double click loads it and runs Auto.
- Keys:
  - Return = Take;
  - Space = Auto;
  - Shift+Space = reverse Auto;
  - `,` `.` `/` = S, M, F;
  - F1–F7 = Main 1–4, DV1, DV2, BKG;
  - 1–7 = Preview;
  - q–u = Superimpose (selectable, no keying in v1).
- FRAMESTORE, STABILIZE, SAVE and the key buttons are drawn and show their pressed look, but do nothing in v1 apart from a status-bar note "not in version 1".

**Tests**
- Widget tests run with `QT_QPA_PLATFORM=offscreen`.
- Tests needing an audio device or a display are tagged `[live]` (Catch2) or carry a `live` CTest label.

## Review Focus

1. **A screen too small for the default zoom** (a 1366×768 or 1920×1080 laptop at 125% scaling): the app picks the largest whole-number zoom that fits the available desktop (minimum 1×) and never scales fractionally. Tested in Task 8.
2. **Toaster data root missing or wrong** (fresh checkout, moved folder): the app starts, explains what is missing, and opens Settings to pick the folder. There is no crash and no half-drawn screen. Tested in Tasks 7 and 10.
3. **Clicks the engine refuses or overrides** (a DVE chosen while ChromaFX is engaged, a hand T-bar during Auto, Take mid-transition): the panel shows the engine's state from the snapshot, not the click, and the refusal reason appears in the status bar. Tested in Tasks 7, 8 and 10.
4. **Closing the app while recording, with live inputs and audio playing:** the recording is finalised and playable, the loop and the audio output stop, and the app exits within 3 s. Tested in Task 10.
5. **High-DPI and a second monitor** (monitor windows dragged to a 150% display): pixels stay crisp N×N blocks and the zoom choices stay whole numbers in device pixels. Tested in Task 9.

struct OutputDevice { std::string name, id; bool isDefault; };
std::vector<OutputDevice> listOutputDevices(std::string* error = nullptr);

class AudioOutput : public ProgramSink {

### Task 10: AppController wiring and the end-to-end app

**Files:**
- Create: `app/src/controller.cpp` (the `AppController : SwitcherActions`), `tests/app/test_app_e2e.cpp`
- Modify: `app/src/main.cpp`, `app/src/main_window.{h,cpp}`, `app/src/toaster_screen.cpp` (snapshot timer)

**Interfaces and behaviour:**
- `AppController` owns `ProgramLoop` (real time, started at launch with the configured inputs), `Recorder` and `AudioOutput`, and holds the monitors as sinks.
  - Actions become `post` / `postChecked` calls. Croutons load through `vt::loadEffect`, cached per path; an unloadable one shows its reason in the status bar.
  - A 30 Hz UI timer pulls `switcherState()` into `ToasterScreen::setState` and shows `lastRefusal` in the status bar.
  - Input changes from Settings become `ProgramLoop::setInput`.
  - File menu: Settings…, Start/Stop Recording (`Ctrl+R`; the file name is `vtoast-YYYYMMDD-HHMMSS.<ext>` in the recording folder), Quit.
  - Status bar: input states, recording state and frames, `LoopStats` late ticks.
- Data root:
  - If `toasterRoot` is invalid at launch, the Switcher tab shows a plain message "Toaster data not found at …" with a button opening Settings → Toaster data.
  - The panel loads after a valid root is chosen, without a restart (Review Focus 2).
- Logging: the app installs a `vt::setLogSink` that only appends to a small lock-protected queue. A UI timer drains it into the status bar and a log view (Help → Log), because the sink runs under a global lock on decoder, capture and recorder threads.
- Stopping a recording runs `Recorder::stop()` off the UI thread (a `std::thread` or `QtConcurrent` task), because it blocks while the queue drains. The menu shows "Stopping…" until it finishes.
- Shutdown: on close, stop the recording (finalise), then the audio output, then the loop, within 3 s (Review Focus 4).
