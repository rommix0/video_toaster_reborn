# Keys and the Superimpose bus: Implementation Plan (Plan 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Toaster's luminance keyer works: a Superimpose source keys over Main against the clip level. Take and the digital moves drop or fly the key as the routing descriptor says. Art Card Key turns the T-bar into the clip control.

**Architecture:**
- **Engine.**
  - A new `key.h/.cpp` holds the key law and the descriptor table.
  - Effects report their routing descriptor and can draw their key-0 area in a fill colour (`RenderCtx::keyFill`).
  - `Switcher` owns the keyer (mode, polarity, level) and the Superimpose bus. It composes the key in `render`, and it applies the Take / fly / drop rules in its existing state transitions.
- **App.** The four key stubs become real controls. The snapshot carries the key state.

**Tech Stack:** C++20 (MSVC 2022, Ninja), Qt 6.8.3, Catch2 (amalgamated).

**Spec:** `docs/2026-10-29-keys-design.md` (approved 2026-10-29). Reverse-engineering source: `../tools/re/KEY.md` (sections cited as "KEY.md §n"); the descriptor table is `../tools/re/key_scan.py`'s output.

## Global Constraints

- Build and test with `tools\build.bat` (configure, build, `ctest -LE live`). Every task ends with the full suite green: `vt_tests`, the app tests and the CLI tests.
- Work on branch `feat/keys`. The owner merges it to main only after saying "Merge to main".
- Clip level L: 0..257, power-up 128. Key mode: power-up off, polarity White (KEY.md §1).
- Clip value: **v = (Black ? L : 257 − L) − 1** for L 1..256. L = 0 shows the Superimpose source alone; L = 257 shows Main alone.
- Art Card Key: L clamped to 0..255, **v = Black ? L : 255 − L**, T-bar = 2L.
- Luma: **Y = (77 R + 150 G + 29 B + 128) >> 8**.
  - Key White: the fill shows where Y ≤ v.
  - Key Black: the fill shows where Y ≥ v.
- Every new GUESS lives in `HardwareGuesses` or is marked `GUESS` in a comment, as the codebase does today.
- The loop-thread rule stays: every UI action is a `ProgramLoop::post` or `postChecked`.

## Calls made while writing this plan (binding; the owner can overrule them)

- **C1. Empty bus.** `Source::None` is added after `Bkg`. Only Superimpose can hold it. Superimpose powers up empty, so no key shows at start; today it powers up as BKG.
- **C2. Overlays and ChromaFX always drop the key.**
  - The effect's key move is `keyMoveFor(routingDescriptor())` only for a digital move (`digitalMove() != None`) that is neither an overlay nor a ChromaFX.
  - Everything else drops the key.
  - Reason: descriptor 19 is the Glitch overlays (an Overlays drawer), and the design shows no key while an overlay is engaged.
- **C3. What a flying move is given.**
  - **Fly on:** the Switcher passes the moving source as both `a` and `b` (and as both `digitalA` and `digitalB`).
  - **Fly off:** the same, with the Superimpose source.
  - **Two-phase:** `a` = Superimpose and `b` = Main.
  - So whichever bus the effect's own role moves, it moves the right picture over `keyFill`.
- **C4. The two-phase half.** The Switcher's own T-bar decides it: `tbar() >= 256` is the second half. An ALGO move's `algoSecondStep` may switch one field earlier or later in Auto.
- **C5. Locks.** The locks of flags 0x1 and 0x400 apply only while a take is open: `auto_ || (tbar_ > 0 && !engaged_)`, never under Art Card Key.
  - **Mode locked:** descriptors that drop the key, plus 5 and 19.
  - **Level locked:** descriptors that drop the key.
  - A locked change is ignored silently (the original reverts it), with no refusal.
- **C6. Flight is live.** Whether the take flies the key is decided at every render and at the end, from the current keyer state. The original picks the descriptor block at every walker call (KEY.md §4).
  - OFF during an unlocked flying move turns it into the plain move, which swaps at the end.
- **C7. Dropping effects empty Superimpose at every end:**
  - the swap at 511;
  - the return to 0 (KEY.md §4, "`$1c6` cleared");
  - Take.
- **C8. Level box.**
  - Dragging changes L by half the horizontal movement in Toaster pixels (right raises it), from L at the press.
  - The text is three zero-padded digits ("005"). The panel's default text is "128".
- **C9. Fill colour.** `keyFill` is `bkgColour(BkgColour::Black)` for Key Black and `bkgColour(BkgColour::White)` for Key White: the Effect Color presets that codes 0xe8 / 0xe9 name (ALGO.md 15.5).
- **C10. Design fix.** In design §2 B, fly on now reads "2, 17". 6 was listed twice; the two-phase entry is the one meant. This is already edited in the design.

## Review Focus

1. **Superimpose source = Main.** The key condition fails, so Program is Main exactly, with no keyed copy over itself. (Task 3 test "a key needs a Superimpose source that is not Main".)
2. **Superimpose is BKG with Snow, or a missing (null) input.** It keys like any picture (Snow's noise; null = black) and never crashes. (Task 3 test "keying BKG Snow and a missing input".)
3. **`keySoftness` out of range** (negative or above 255) is clamped where used. (Task 1 test "lumaKey softness".)
4. **A level or mode change during a dropping take** is ignored, and the old values are still in force after the take. (Task 4 test "locks during a take".)
5. **A framestore load with DV on Superimpose.** The existing target rule keeps working with the renamed bus, and `Source::None` on Superimpose never counts as DV. (Task 3 test "load target with Superimpose".)

### Task 1: The key law and the descriptor table

**Files:**
- Create: `engine/include/vt/key.h`, `engine/src/key.cpp`, `tests/test_key.cpp`
- Modify: `engine/include/vt/hardware_guesses.h` (add `keySoftness`), `engine/CMakeLists.txt`, `tests/CMakeLists.txt`

**Interfaces:**
- Produces (namespace `vt`):
  - `enum class KeyMode { Off, Black, White };` (the lit button)
  - `enum class KeyMove { Drops, FliesOn, FliesOff, TwoPhase };`
  - `inline constexpr int kKeyLevelMax = 257;`
  - `KeyMove keyMoveFor(uint32_t descriptor);`
    - 2, 17 → FliesOn;
    - 3, 18 → FliesOff;
    - 5, 6, 19 → TwoPhase;
    - every other value → Drops (including 0, the unused 7, 9, 10, 13–16, 21 and 28, and unknown values).
  - `bool keyModeLocked(uint32_t descriptor);` true for Drops, 5 and 19.
  - `bool keyLevelLocked(uint32_t descriptor);` true for Drops.
  - `uint8_t keyLuma(Rgba8);` the luma in Global Constraints.
  - `int keyClip(bool black, int level);` level clamped to 1..256, then (black ? L : 257 − L) − 1.
  - `void lumaKey(const Frame& fill, const Frame& background, const Frame& signal, int v, bool black, int softness, Frame& out);`
    - Per pixel: Y = keyLuma(signal), d = black ? Y − v : v − Y, s = clamp(softness, 0, 255).
    - Fill share w: if s == 0, w = d ≥ 0 ? 255 : 0; else w = clamp(((2d + s) · 255) / (2s), 0, 255) (integer division).
    - out = (background · (255 − w) + fill · w + 127) / 255 per channel (`detail::mix255`'s rounding; write it locally, since effect_detail.h is not public), alpha 255.
    - Works pixel by pixel, so `out` may alias any input.
  - `HardwareGuesses::keySoftness = 0`: comment it as a HARDWARE GUESS (design §4; the manual calls an analog key sharp).

| moment | Drops | FliesOn | FliesOff | TwoPhase |
|---|---|---|---|---|
| take start (`beginTransitionIfIdle`) | keyer off | DV input = Preview's input | DV input = Superimpose's input | DV input = Superimpose's input |
| render while running | the effect as today, no key | effect(a = b = Preview) over keyFill, keyed over Main | effect(a = b = Superimpose) over keyFill, keyed over Main | effect(a = Superimpose, b = Main) over keyFill, keyed over Main (T-bar < 256) or over Superimpose (≥ 256) |
| 511 (`finishAt511`) | swap; Superimpose emptied | no swap; Superimpose = Preview's source; keyer on | no swap; Preview = Superimpose's source; Superimpose emptied; keyer on | no swap; buses unchanged |
| back to 0 (`arriveAt0`) | Superimpose emptied; keyer stays off | Superimpose emptied | Preview = Superimpose's source; Superimpose emptied | Preview = Superimpose's source; Superimpose emptied |
| `take()` | design §2 B Take steps | the same | the same | the same |

- Modify: `engine/include/vt/switcher.h`, `engine/src/switcher.cpp`

**Interfaces:**
- Consumes: Task 2 `isArtCardKey()`; Tasks 3–4 keyer state.
- Produces: behaviour per design §2 C. One private member: `Source cardSaved_ = Source::None`, the source the card restores.
  - **`setEffect(card)`:**
    - keyer on;
    - `cardSaved_` = Superimpose (if not None);
    - L = min(L, 255);
    - `tbar_` = 2L.
  - **Leaving the card** (`setEffect` of anything else): keyer off, Superimpose None.
  - **`setTBar(pos)`:**
    - no transition: `tbar_` = pos, L = pos / 2;
    - keyer on;
    - an empty Superimpose restored from `cardSaved_`.
  - **`autoTransition`:** does nothing.
  - **`setKeyLevel(L)`:** L clamped to 255 and `tbar_` = 2L.
  - **`setKeyMode(Black/White)`:** re-applies the card (keyer on, bus restored).
  - **`setKeyMode(Off)`:** keyer off, `cardSaved_` = Superimpose if it is not None, Superimpose None. The card stays loaded, and the next T-bar move re-applies it.
  - **`take()`:** the cut (design §2 B steps), then the card re-applies: Superimpose restored, `tbar_` = 2L.
  - **`render`:** with the card loaded, keyer on and Superimpose ≠ None, `lumaKey(fill = Main, background = Preview, signal = Superimpose, v = Black ? L : 255 − L, ...)`. Otherwise Main.
  - **Locks** never apply (C5). FREEZE / LIVE / grab and `loadStill` keep their transitionActive / T-bar rule, so they are refused while `tbar_` > 0.
