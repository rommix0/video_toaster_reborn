# Plan 4: ALGO Switcher Moves, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play the ALGO croutons (digital moves, wipes and fades) in the engine and the app. Their per-step control tables must equal the original Switcher's byte for byte.

**Architecture:**
- **VM.** A C++ port of the verified Python reference (`../tools/re/algo_ref.py`) turns the effect position t into a step: an H row, a V table and ranges for moves; spans and a band for wipes; a level for fades.
- **Moves** become a `DveControl` and are drawn by the existing `renderDve`. Wipes and fades have small renderers of their own.
- **`AlgoEffect`** keeps a VM per take and steps it in the order the Switcher renders. The Switcher tells effects which take they are in, and which Auto step is due.

**Tech stack:** C++20 `vt_engine`, Catch2, Qt Test (one app test), Python 3 references (`python -P -E`).

**Spec:**
- Design: `docs/2026-10-28-algo-design.md`.
- Reverse-engineering reference: `../tools/re/ALGO.md`, which is binding for every rule cited as §N below.

## Global Constraints

- Branch `plan4-algo`. The engine stays free of Qt and FFmpeg.
- Build and test with `cmd /c tools\build.bat` from the repo root. It must be green before every commit.
- Run Python as `python -P -E`.
- Preserve each file's existing line endings; `git diff --stat` must not show whole-file rewrites.
- **Bit-exact:** the C++ VM must equal the golden data from the Python reference, CRC for CRC. Do not "fix" the reference.
- **Guesses:** every hardware guess lives in `vt::HardwareGuesses` or is marked `GUESS` in a comment that cites the ALGO.md section.
- **Out of scope** (design §3):
  - Art Card Key (kind 5): stays refused.
  - The four Bar stills: they are ILBM/ANIM croutons, not ALGO, and stay refused as they are.
  - Interactive positioning of kinds 3 and 4.
  - Opcodes 15, 16 and 18–20: a program that uses one is refused.
  - Flag 0x100: ignored.
  - Flag 0x80 on a digital move: refused; no shipped program has it.
- **Speed tags are fields** (ALGO.md §3, proven). An ALGO effect's `durationTicks` is the tag value itself, not twice it.

## Review Focus

1. **Effect changed or take aborted mid-take.** A new take must start from a fresh VM, never from the old buffers. (Task 4: `algo take resets`)
2. **Speed changed during Auto.** The Switcher rescales its accumulator; the Auto step must stay within 1..N and must not index past the program. (Task 4: `algo auto step clamps`)
3. **Reverse Auto, or forward Auto started from a T-bar position above 0.** These have no Auto step, so the T-bar mapping applies with no crash. (Task 4: `algo auto from mid T-bar uses the T-bar`)
4. **Effect colour that is a custom word or Snow on a border move.** The border falls back to colour index 0 (Black), with no crash. (Task 3: `border fill for custom and snow colours`)
5. **The same position rendered on many ticks** (T-bar held still while ticks render). The frames must be identical and the VM must not step again. (Task 4: `algo repeated render does not step`)

```cpp
enum class AlgoKind { Digital = 0, Wipe = 1, Fade = 2, PosDigital = 3, PosWipe = 4, ArtCardKey = 5 };

struct AlgoStep {
    // digital (kinds 0, 3)
    std::array<uint8_t, 0x170> h{};  // H row; cells 0..191 used
    std::array<uint8_t, 0xf4> v{};   // V table; control lines 0..240 used
    int cellLo = 0, cellHi = 0;
    int lineLo = -1, lineHi = -1;    // -1: no line shows the row
    // wipes (kinds 1, 4)
    std::vector<std::pair<int, int>> spans;  // per channel ($14, $16); -1 = none
    int pixelLo = 0, pixelHi = 0, ink = 0, bandLo = -1, bandHi = -1, bandInk = 0;
    bool inverse = false;            // flag 0x80 (§6)
    // all kinds
    int level = -1;                  // channel 23 word 0 with flag 0x10, else -1
};

class AlgoVm {
public:
    // payload = tag 0x1000001C bytes, kind = tag 0x80000063 (0..4), colour = digital Effect
    // Color index 0..7 (ALGO.md §15.5). Throws std::runtime_error for kind 5, a malformed
    // payload, opcodes 15/16/18+, or flag 0x80 on a digital kind.
    AlgoVm(std::vector<uint8_t> payload, int kind, int colour);
    uint32_t flags() const;
    AlgoKind kind() const;
    const AlgoStep& step(uint32_t t);  // t in 16.16, 0..0x10000; state carries over (§15.1)
};

uint32_t algoTBarT(int pos, uint32_t flags);       // tbar_t; pos clamped to 0..511
uint32_t algoAutoT(int k, int n, uint32_t flags);  // auto_ts(n, flags)[k - 1]; k clamped to 1..n
// The routing walker's step for these effects (§15.2): T-bar >= 256, or in Auto the unfolded
// k * floor((flags & 8 ? 0x20000 : 0x10000) / n) >= (flags & 8 ? 0x10000 : 0x8000).
bool algoSecondStep(int tbar, int autoStep, int n, uint32_t flags);
```

```cpp
uint8_t borderFill = 23;      // fill code (16..23) drawn where a moving cell's line is kDveColourLine
inline constexpr uint8_t kDveColourLine = 0xfc;  // §15.5: DV line 0xfc holds the border colour

DveControl algoControl(const AlgoStep&);  // §5.3: key = 255 - H[c] inside the line and cell ranges, else 0; line = V[k]
int algoBorderFill(int colourIndex);      // 23 - index for 0..7; 23 (Black) otherwise
```

- **`renderDve` changes:**
  - A moving cell (v ≥ 64) whose `line[k] == kDveColourLine` draws `borderFill` (the same 75 % fill as key codes 16..23).
  - Any other line above 240 still reads line 240.
  - The source x becomes `clamp(4 * (sc - dveSourceCellOffset) + inner, 0, 767)`.
- **`renderAlgoWipe`** (§6; the polarity is a GUESS, documented at the function).
  - **Span row bit at raster x (0..767):**
    1. 1 if x lies in a span (s0 ≥ 0, s0 ≤ x ≤ s1) and `ink` is 1;
    2. else 0 if it lies in a span and `ink` is 0;
    3. else `ink ^ 1` if `pixelLo ≤ x ≤ pixelHi`;
    4. else 0.
  - **Row choice for raster line y (0..481):**
    - Without flag 0x80: the span row if `bandLo ≥ 0` and `bandLo ≤ y ≤ bandHi`; otherwise the constant row `bandInk`.
    - With `step.inverse` (flag 0x80): the constant row `bandInk ^ 1` inside the band and the span row outside it.
  - **Constant rows:** row 0 is all 1 and row 1 is all 0.
  - **Output:** bit 1 = B, bit 0 = A, copied pixel for pixel.
- **`mixLevel`:** each RGB channel is `(in0 * (255 - L) + in1 * L + 127) / 255`; alpha is 255.

**Rules for `AlgoEffect`:**
- **Refusals.** Each one returns nullptr and sets `why`:
  - kind 5: `"Art Card Key needs keys (not built yet)"`;
  - no tag 0x1000001C: `"ALGO effect without a program"`;
  - the `AlgoVm` constructor throws: `"ALGO program not supported: " + what()`;
  - a digital kind whose descriptor is not 2, 3, 5 or 6, a fade whose descriptor is not 1 or 8, or a wipe whose descriptor is not 4: `"ALGO routing descriptor N not supported"`.
- **Basics.** `usesDvMemory()` is true for kinds 0 and 3 only. `frameCount()` is 1.
- **State.** `render` is const, so the state is `mutable` and covers the current take number, the last step key, the VM and the last step. The Switcher renders from one thread; say so in the class comment.
  - **New take:** when `ctx.take` differs from the stored number, build a fresh VM with colour index `algoColourIndex(ctx.colour)`.
  - **Step key:** `ctx.autoStep` if it is at least 1, else −1 − tbar. A render whose key equals the last step's key reuses the last step and does not step the VM.
  - **Effect position:** `t = algoAutoT(autoStep, N, flags)` with N = `timing().durationTicks[ctx.speed]` (Medium when `speed` is unset); otherwise `algoTBarT(tbar, flags)`.
  - **Second step:** `algoSecondStep(tbar, autoStep, N, flags)`.
- **Pictures by kind:**
  - **Digital (0 and 3):**
    1. `control = algoControl(step)`, then `control.borderFill = algoBorderFill(algoColourIndex(ctx.colour))`.
    2. Pick moving and background (design table):
       - desc 2: B over A;
       - desc 3: A over B;
       - desc 5: A over A, then B over B on the second step;
       - desc 6: A, then B on the second step, over a frame filled with `ctx.background`.
    3. `renderDve(control, moving, background, {}, out, ctx.guesses)`.
    4. If `step.level >= 0`, then `out = mixLevel(background, out, level)` (§15.4; GUESS).
  - **Wipe (1 and 4):** `renderAlgoWipe(step, a, b, out)`.
  - **Fade (2):** L = `step.level` clamped to 0..255, or 255 when it is −1.
    - desc 1: `mixLevel(a, b, L)`.
    - desc 8: `mixLevel(a, matte, L)` on the first step and `mixLevel(b, matte, L)` on the second, where matte is a frame filled with `ctx.background`.
- **Switcher:**
  - `take_` is incremented in `setEffect`, and in `beginTransitionIfIdle` when `!transitionActive()`.
  - `autoFrom0_` is set in `autoTransition` (forward, `tbar_ == 0 && !auto_`). It is cleared when the hand moves the T-bar, on any reverse Auto, and when the Auto ends.
  - `render` sets `ctx.take = take_` and `ctx.colour = effectColour()`. While `auto_ && autoFrom0_ && autoDir_ == Forward`, it also sets `ctx.autoStep = min(autoDur_, autoAcc_ / 511 + 1)`.
