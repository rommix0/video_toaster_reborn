# vtoast_reborn Plan 1 — Engine core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless C++ library (`vt_engine`) that reads the original Toaster crouton files and renders every version-1 effect (cut, dissolve, gradient wipes, animated wipes, bit-exact DVE moves, ChromaFX) through a Toaster-style switcher model, plus a command-line renderer (`vt_render`) to look at the results.

**Architecture:** Plain C++20 static library with no Qt or FFmpeg dependency. Decoders are ported from the Python reference tools and tested to be byte-identical against golden data those tools generate. Effects render into a fixed native raster (768×482 progressive RGBA). Plan 2 (FFmpeg video/audio I/O) and Plan 3 (Qt application and assets) build on this library and are written after it lands.

**Tech Stack:** C++20, MSVC 14.44 (VS 2022 Build Tools), CMake 3.31 + Ninja, Catch2 v3 (amalgamated, vendored), Python 3.13 + numpy for golden data.

**Spec:** `vtoast_reborn/docs/2026-10-17-switcher-design.md`

## Global Constraints

- Language C++20; the engine library must not include or link Qt or FFmpeg.
- Windows first; build with MSVC from `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat`.
- Internal raster (this plan's call, see "Decisions" below): `kRasterW = 768`, `kRasterH = 482`, progressive, 59.94 frames/s; pixel type RGBA 8-bit.
- No rescaling, filtering or blending of effect data; DVE reads exactly one source pixel per output pixel.
- Overscan margins are never filled or invented; raw data is kept.
- Effect timing: ANIM Slow/Medium/Fast tags are fields-per-anim-frame (defaults 3/2/1, 0 = disabled); duration in frames = (fields × frameCount + 1) / 2; T-bar range 0–511.
- Background colours are values read from `switcher.main`, never guessed.
- Where a value lives in the Toaster hardware and not the code, it is a named, documented field of `HardwareGuesses`, adjustable, never a buried constant.
- When the Python reference and the disassembly disagree, the disassembly wins.
- Original data is read from the Toaster tree; tests find it through the `VT_DATA_ROOT` compile definition (the folder containing `4.2/` and `3.1/`).

## Decisions this plan makes (owner may override)

- **Raster = 768×482**, the effects' own grid (192 four-pixel cells × 241 lines per field, two line parities). Every wipe and DVE control frame then lines up with the picture with no registration offset. Framestores (752×480) will be placed at an offset decided in the framestore work (after version 1).
- **T-bar → animation frame:** `frame = min(N − 1, tbar × N / 512)`.
- **Golden data** is generated by a Python script from the existing reference tools, committed as JSON-lines files, and compared through CRC-32 (zlib polynomial) of raw buffers.
- Git repository at `vtoast_reborn/` (commits are part of the plan the owner approves).

## Review Focus

1. Effects whose files are damaged at the end (the Python decoder drops the last 1–2 frames) must still load and play the good frames, not crash or refuse. Test in Task 4.
2. A crouton whose speed tag is 0 for the requested speed (e.g. Page Peel has no Slow) must fall back to the effect's default speed, not divide by zero or play in zero frames. Test in Task 5.
3. 3.1 effects wrapped in Amiga hunk files must load exactly like 4.2 IFF files. Test in Task 4.
4. Starting a DVE move while ChromaFX is engaged (they share DV memory) must be refused cleanly with a reason, not corrupt either effect. Test in Task 11.
5. Moving the T-bar backwards, or reversing an Auto mid-way, must show the matching earlier frame, never a stale frame left from delta decoding. Test in Task 11.

### Task 8: Effect interface, cut, dissolve, gradient and animated wipe players

**Files:**
- Create: `engine/include/vt/effect.h`, `engine/src/effect_basic.cpp` (cut, dissolve), `engine/src/effect_gradient.cpp`, `engine/src/effect_anim.cpp`, `engine/include/vt/hardware_guesses.h`, `engine/src/effect_factory.cpp`

**Interfaces:**
- Consumes: Tasks 2–7.
- Produces:
  - `struct vt::HardwareGuesses { int gradientSoftness = 0; float dveShadowOpacity = 0.5f; int dveCellPixel = -1; float chromaLumaOffset = 17.5f; };` — documented in the header: softness = gradient levels over which the wipe edge ramps (0 = hard); `dveCellPixel` −1 = read the same offset inside the source cell as the output pixel has in its cell, 0–3 = always that offset.
  - `struct vt::RenderCtx { Rgba8 background; uint32_t frameNumber; HardwareGuesses guesses; };`
  - `class vt::Effect { public: virtual ~Effect(); virtual std::string name() const = 0; virtual Timing timing() const = 0; virtual int frameCount() const = 0; virtual void render(int tbar, const Frame& a, const Frame& b, Frame& out, const RenderCtx&) const = 0; virtual const Sound* sound() const { return nullptr; } virtual bool usesDvMemory() const { return false; } };`
  - `std::unique_ptr<Effect> vt::makeCut(); std::unique_ptr<Effect> vt::makeDissolve();`
  - `std::unique_ptr<Effect> vt::loadEffect(const std::filesystem::path&, std::string* whyNot = nullptr);` — returns gradient, anim, DVE (Task 9) or ChromaFX (Task 10) effects; `nullptr` with a reason for ALGO/MAIN/CTRL and unsupported files.

Behaviour:
- Gradient (ILBM, `gray = gray_lut(bm)[index]`): pixel shows B where `gray ≥ 255 − tbar × 255 / 511` (bright revealed first); with `gradientSoftness` > 0 a linear ramp of that many gray levels.
